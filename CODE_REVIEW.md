# ШАГ 2: РЕВЬЮ КОДА И ИСПРАВЛЕНИЕ НЕДОЧЕТОВ

## 🔴 КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. БЕЗОПАСНОСТЬ - Пароли хранятся в открытом виде
**Файл:** `models.py`, `main.py`
**Проблема:** Пароли не хешируются, хранятся как plain text
**Риск:** Критический - утечка БД = утечка всех паролей

### 2. ОТСУТСТВИЕ ВАЛИДАЦИИ JWT
**Файл:** `main.py`
**Проблема:** Токены не проверяются, любой может подделать `access_token`
**Риск:** Высокий - полный доступ к любому аккаунту

### 3. SQL INJECTION (потенциальный)
**Файл:** `main.py` - все эндпоинты с `userId`
**Проблема:** userId берется из query string без валидации
**Риск:** Средний - SQLAlchemy защищает, но лучше валидировать

### 4. ОТСУТСТВИЕ RATE LIMITING
**Проблема:** Нет защиты от DDoS и брутфорса
**Риск:** Высокий - сервер можно положить

### 5. CORS - слишком открытый
**Файл:** `main.py:17-23`
**Проблема:** `allow_origins` включает localhost, но в проде будет уязвимость
**Риск:** Средний - CSRF атаки

## ⚠️ ВАЖНЫЕ НЕДОЧЕТЫ

### 6. Отсутствие try-except в критических местах
**Файл:** `main.py` - большинство эндпоинтов
**Проблема:** Ошибки БД приводят к 500 вместо понятных сообщений
**Пример:** Строки 225-280 (dashboard), 307-333 (transactions)

### 7. Нет логирования
**Проблема:** Невозможно отследить ошибки в продакшене
**Риск:** Низкий, но критично для поддержки

### 8. Hardcoded значения
**Файл:** `main.py`
- Строка 19: `allow_origins` - должно быть в .env
- Строка 438: `admin@admin.com` - хардкод админа

### 9. Async/Sync конфликты
**Файл:** `llm_agent.py`
**Статус:** ✅ ИСПРАВЛЕНО (используется AsyncOpenAI)

### 10. Отсутствие транзакций БД
**Файл:** `main.py` - эндпоинты с несколькими операциями
**Проблема:** Если одна операция упадет, данные будут несогласованными
**Пример:** Строки 335-377 (add_transaction) - обновляет баланс и создает транзакцию
